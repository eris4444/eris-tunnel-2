## معرفی

**Eris Tunnel 2** یک اسکریپت Bash برای نصب، ساخت، مدیریت، مانیتورینگ، تست و عیب‌یابی تانل‌های معکوس مبتنی بر **Musixal/Backhaul** است.

> **ایران = سرور (Server)**
> **خارج = کلاینت (Client)**
> پیرکد روی سرور ایران ساخته می‌شود و روی سرور خارج پیست می‌شود.

هر تانل در یکی از **دو حالت** ساخته می‌شود که از منو انتخاب می‌کنید:

| حالت | چیزی که به کاربر می‌دهد |
| --- | --- |
| **Port forward** | پورت‌هایی روی سرور ایران که به پنل روی سرور خارج می‌رسند |
| **SOCKS5 proxy** | یک پروکسی SOCKS5 روی سرور ایران که ترافیکش از خارج بیرون می‌رود |

## حالت پروکسی SOCKS5

به‌جای فوروارد کردن پورت‌های ثابت، می‌شود تانل را به‌صورت یک پروکسی خروجی
تحویل داد. سرور SOCKS5 **روی خودِ سرور ایران** اجرا می‌شود و از طریق تانل به
یک خروجی روی سرور خارج زنجیر (chain) می‌شود:

</div>

```
app -socks5-> IRAN 0.0.0.0:PROXY_PORT      سرور socks5 روی ایران
                 chained to
              IRAN 127.0.0.1:BRIDGE_PORT   backhaul، فقط روی loopback
                 tunnel
              KHAREJ 127.0.0.1:EXIT_PORT   خروجی socks5
                 out to the internet
```

<div dir="rtl">

آی‌پی خروجی که سایت مقابل می‌بیند، آی‌پی **سرور خارج** است.

هنگام ساخت تانل ایران گزینه `SOCKS5 proxy` را انتخاب کنید، بعد سرور خارج را
پیر (pair) کنید — خودش از روی پیرکد خروجی‌اش را در یک مرحله بالا می‌آورد. تانل
موجود را هم می‌شود از `Manage tunnels -> [9] SOCKS5 proxy` بین دو حالت جابجا کرد.

| | |
| --- | --- |
| سرویس، هر دو طرف | `eris-proxy@<tunnel>.service` |
| تنها پورت عمومی | فقط لیسنر socks ایران، و همیشه یوزر و پسورد می‌خواهد |
| پرش تانل | `127.0.0.1:BRIDGE_PORT` روی ایران — جز پروکسی محلی هیچ‌کس به آن نمی‌رسد |
| موتور پروکسی | `gost`، در صورت نیاز از ریلیزهای گیت‌هاب نصب می‌شود |
| یوزر و پسورد | اختیاری — از خودت پرسیده می‌شود و مقدارش را هم خودت می‌دهی |
| محل نگهداری | `proxy.env` با دسترسی ۶۰۰، هرگز داخل فایل unit نیست |
| پروتکل | فقط TCP؛ حالت UDP ASSOCIATE منتقل نمی‌شود |

### یوزر و پسورد اختیاری است

موقع ساخت تانل پروکسی می‌پرسد «پروکسی با یوزرنیم و پسورد محافظت بشود؟». اگر
بله بگویی، خودش یوزرنیم و پسوردِ دلخواهت را می‌پرسد و ست می‌کند؛ اگر نه بگویی
هیچی نمی‌گذارد. گزینه `[3] Credentials` در صفحه پروکسی همین سؤال را بعداً هم
می‌پرسد، روی هر دو طرف. زدن Enter در هر پرامپت، پیشنهاد تولیدشده را قبول می‌کند.

> **بدون یوزر و پسورد یعنی هر کسی که به `PROXY_PORT` برسد می‌تواند از پروکسی
> استفاده کند**، و هر چه بفرستد از آی‌پی سرور خارج تو بیرون می‌رود — که راه
> خوبی است برای بلک‌لیست یا تعلیق شدن آن سرور. اسکریپت موقع انتخاب هشدار
> می‌دهد و تا وقتی خاموش است هشدار را در صفحه وضعیت نگه می‌دارد. فقط وقتی
> این کار را بکن که چیز دیگری دسترسی به آن پورت را محدود کرده باشد.

هر کدام را انتخاب کنی، باید دو طرف یکی باشند — پیرکد همین را حمل می‌کند.

نکته‌های مهم:

- پورت پل (bridge) فقط لوله‌کشی داخلیِ سرور ایران است. روی loopback بسته
  می‌شود، در پیرکد نیست، و لازم نیست در فایروال بازش کنید. فقط `PROXY_PORT`
  را برای کاربران و پورت تانل را برای سرور خارج باز کنید، نه چیز دیگری.
- حالت پروکسی به ترنسپورت TCP نیاز دارد؛ `udp` رد می‌شود.
- تا وقتی تانل در حالت پروکسی است، لیست پورت‌های کاربر نگه داشته می‌شود ولی
  فوروارد نمی‌شود؛ پس برگشت به حالت فوروارد آن را دست‌نخورده برمی‌گرداند.
- عوض کردن پورت پروکسی یا یوزر/پسورد سمت ایران یعنی باید سمت خارج را دوباره
  پیر کنید، یا همان مقادیر را دستی روی آن ست کنید.

گزینه `[t] Test it` از داخل پروکسی درخواست بیرون می‌فرستد و آی‌پی خروجی را
نشان می‌دهد — از سمت ایران کل زنجیره را می‌سنجد. و `[5] Client settings` یک خط
آماده `socks5://user:pass@host:port` می‌دهد.

## امنیت

تمام سخت‌سازی‌های مسیرهای ورود داده از بیرون سرور در این نسخه حفظ شده است:

- پیرکد پیش از استفاده به‌طور کامل اعتبارسنجی می‌شود. توکن فقط می‌تواند شامل
  `A-Z a-z 0-9 + / = . _ @ : -` باشد و نگاشت پورت‌ها فقط رقم و جداکننده. در
  نتیجه یک پیرکد دستکاری‌شده نمی‌تواند کاراکترهای خطرناک شل را وارد سرور کند.
- فایل `meta.conf` دیگر توسط شل `source` نمی‌شود؛ به‌جای آن به‌عنوان داده و
  بر اساس فهرست سفید کلیدهای شناخته‌شده خوانده می‌شود.
- اعتبارسنجی IPv4 و دامنه، مقادیر خارج از بازه و دامنه‌هایی که با `-` شروع
  می‌شوند را رد می‌کند.
- تمام فایل‌های موقت با `mktemp` ساخته می‌شوند و هیچ مسیر قابل حدس زدنی زیر
  `/tmp` باقی نمانده است.

## مهاجرت از نصب قبلی

مسیر داده‌ها عوض شده، پس تانل‌های قبلی خودبه‌خود شناسایی نمی‌شوند:

</div>

```
systemctl stop 'backhaul@*'

systemctl start 'backhaul@*'
```

<div dir="rtl">

## داشبورد وب حذف شده

رابط وب داخلی Backhaul (یعنی `sniffer` و `web_port`) دیگر توسط این مدیر ارائه
نمی‌شود، و کانفیگ‌های تولیدی آن را صریحاً خاموش می‌کنند تا هیچ لیسنر HTTP باز
نشود. اگر تانلی از نسخه قدیمی هنوز داشبورد وب داشته باشد، اسکریپت در استارت
بعدی تشخیص می‌دهد و پیشنهاد خاموش کردنش را می‌دهد.

داشبورد زنده‌ای که در منوی اصلی هست، یک نمای ترمینالی است و دست‌نخورده مانده.

## هسته

هسته تانل از پروژه **Musixal/Backhaul** می‌آید. Eris Tunnel 2 یک لایه
مدیریتی مستقل است که بر پایه پروژه MIT با نام **darktunnelmika/dark-backhaul**
ساخته شده و وابستگی رسمی به هیچ‌کدام از پروژه‌های بالادست ندارد.
